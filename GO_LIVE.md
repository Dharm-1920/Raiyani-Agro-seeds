# Publish Raiyani Agro Seeds

**Current selection: free hosting for the fully working shop. Follow [FREE_HOSTING.md](FREE_HOSTING.md).** The current `render.yaml` runs the entire shop on Render Free with MongoDB image storage. The older Vercel/paid-backend approach below is an alternative and is not the selected deployment plan.

Status: **live on Render Free** at [raiyaniagroseeds.onrender.com](https://raiyaniagroseeds.onrender.com/). The separate Atlas database has been migrated and public checks passed for secure admin login, products, migrated images, direct routes, account privacy, notifications, saved carts and Gujarati invoices. No paid hosting plan was activated. See the current free-hosting guide for administration details.

The frontend can use Vercel for a public `*.vercel.app` address. This shop also needs its Express API, MongoDB database, and uploaded images online. Uploading the frontend alone will not make accounts or purchases work.

Vercel's Hobby plan is restricted to personal, non-commercial use. A working business shop needs an eligible commercial plan (Pro is listed at USD 20/month before taxes and usage) or another frontend host. Review the actual checkout price before upgrading; no subscription is authorized by this guide. Sources: [Hobby usage limits](https://vercel.com/docs/plans/hobby), [Vercel pricing](https://vercel.com/pricing).

## 1. Prepare accounts and data

- Sign in to Vercel, GitHub, Render and MongoDB Atlas in your own browser. Keep passwords and database credentials out of chat and source control.
- Create a private GitHub repository for this project. The existing ignore rules exclude local secrets and uploads. Review the files before uploading.
- Create an Atlas database and a dedicated database user. Allow connections from the backend service's outbound IP addresses.
- Migrate the existing local shop database to Atlas using MongoDB Database Tools or a verified database migration. This preserves actual products, customers and orders; a fresh empty database will not show the local shop's data. Do not run sample seeding over the migrated shop.
- Copy the existing uploaded image files separately to the backend's persistent upload directory. Images under the client's public assets are deployed with the frontend.

## 2. Host the backend

The older Vercel arrangement requires a separately configured backend with durable image storage. A paid disk is optional only if selecting that older approach; the current `render.yaml` uses database image storage on a free instance instead. Use the free-hosting guide above for the chosen setup.

Import the private repository in Render. Set `MONGO_URI` securely to the Atlas connection string. Set `CLIENT_URL` to the eventual Vercel production origin; update it after Vercel assigns the URL. `JWT_SECRET` is generated by the blueprint. Set the shop's real UPI receiving ID if enabling QR payments.

The service uses the server directory, `npm ci`, and `npm start`. Uploaded product photos live at `/var/data/uploads`. Copy the local uploaded files there with their original filenames. Confirm `https://YOUR-ACTUAL-BACKEND/api/health` returns `{"ok":true}`.

Use a strong production admin password. If migrating local admin accounts, update their passwords before opening the shop publicly. Do not reuse the development example password.

## 3. Configure and publish Vercel

Once the real backend URL is known, run this command from the project root, replacing the example URL:

```powershell
node scripts/prepare-vercel.mjs https://YOUR-ACTUAL-BACKEND.onrender.com
```

This creates `client/vercel.json` with API and image proxy rules plus support for opening and refreshing client routes. Commit that generated file to the private repository.

Import the repository in Vercel. Choose **Root Directory: client**, **Framework: Vite**, **Build: npm run build**, **Output: dist**. Choose the project name, such as `raiyani-agro-seeds`, subject to availability. Deploy and use the production URL Vercel actually returns.

Update Render's `CLIENT_URL` to that exact HTTPS origin. API requests go through Vercel under the same origin, allowing the existing secure login cookies to work. Do not put database credentials or JWT secrets in Vite environment variables.

## 4. Verify before sharing

Check sign in, private profile/address data, products and images, admin product uploads, a test order, QR receiving details, invoices, notification delivery, and direct route refreshes. Confirm uploaded photos survive a backend restart. The local development site remains separate from production after migration.
